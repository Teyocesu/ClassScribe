# ClassScribe v0.8.0 — captura confiable, master durable y recuperación

Estado: **CANÓNICA / REBASELINE DE RELEASE CHECKPOINT #1**

Baseline canónico: `bad506533e683eabe66870bd88f21ff59f43f3eb`
Branch: `v0.8.0-development`

Fecha: 2026-08-26
Alcance: frontera funcional y gates de release de v0.8.0; no autoriza por sí solo una implementación.

Esta es la única SPEC de ingeniería de v0.8.0. `PLAN.md` ordena el trabajo y puede cambiar; si discrepan sobre requisitos o invariants, prevalece esta SPEC.

## 1. Objetivo

Hacer que iniciar, rebindear y detener una clase sea una operación observable,
cancelable y acotada; capturar explícitamente una aplicación o todo el audio de
salida con consentimiento por intento; conservar un master durable fiel,
separado de su derivado ASR; y recuperar fallos sin perder audio, transcript
original ni correcciones humanas.

La experiencia conceptual debe ser común en macOS y Windows. Las implementaciones usarán las APIs nativas de cada sistema y no compartirán abstracciones de captura artificiales.

La aceptación de VAD/ASR, la renovación completa de speakers y la localización
completa quedan expresamente fuera de la frontera estable de esta versión; se
conservan como roadmap posterior dentro de esta SPEC.

### 2.3 Auditoría de idioma y aceptación ASR

#### macOS / Parakeet

- ClassScribe pasa correctamente `TranscriptionLanguage` a `FluidAudio.Language` en vivo y al final.
- FluidAudio 0.15.5 agrupa español, inglés y francés bajo el mismo script latino. `TokenLanguageFilter` separa scripts, no estos tres idiomas.
- Para idiomas latinos no ingleses, el decoder agrega una lista finita de tokens considerados exclusivos del inglés. No es una restricción completa de idioma.
- ClassScribe no ejecuta el VAD de FluidAudio antes de inferencia. El umbral energético existente sólo ayuda a separar párrafos.
- Se acepta cualquier texto no vacío devuelto por Parakeet. Por ello, silencio/ruido ambiguo puede llegar al decoder y explotar el prior inglés del modelo.
- El vocabulario técnico CTC se aplica al procesamiento final; el vivo no usa ese booster.

Conclusión: el idioma llega al motor, pero la implementación no demuestra el invariant para idiomas que comparten script. El defecto no se resuelve con detección posterior de idioma; requiere gating de voz antes de inferencia y aceptación próxima al decoder. Estos puntos quedan en el gate posterior de Fase 3; no son un criterio de la frontera estable de §13.

#### Windows / Whisper

- `WhisperProcessorBuilder.WithLanguage(languageCode)` fuerza el idioma seleccionado y el prompt técnico se pasa al vivo y al final.
- ClassScribe acepta todo segmento no vacío. No usa VAD, probabilidad de no-speech, log probability ni energía para aceptar el resultado.
- El prompt técnico puede reforzar una alucinación cuando no hay voz; nunca debe sustituir al gate de voz.

Conclusión: la restricción de idioma está configurada, pero falta la mitad de aceptación. Se combinarán VAD/energía con señales nativas que Whisper.net pueda exponer; si el wrapper no expone no-speech/logprob, se agregará la extensión mínima o el VAD previo será la señal primaria documentada.

### 2.4 Auditoría de diarización y hablantes

- En macOS, el label interno `S0` se presenta como `Persona 0`: bug determinista de mapping. Windows suma uno y presenta `Persona 1`.
- Un único cluster puede representar una clase de un hablante o un colapso. Hoy no se persiste evidencia suficiente para distinguirlos.
- La asignación ASR↔speaker usa mayor solapamiento temporal. Sin solapamiento pero con spans, elige el speaker más cercano con confianza `0.25`; sin spans conserva unknown.
- La “confianza” es principalmente cobertura temporal, no calidad de clustering. Windows asigna calidad `1` a todos los spans, por lo que no es comparable.
- Los IDs persistidos son labels efímeros del motor y pueden cambiar al reprocesar.
- Reprocesar reconstruye speakers, profesor y review; puede borrar correcciones manuales.
- macOS guarda embeddings/referencias por materia con umbral `0.62`, sin margen contra el segundo candidato ni versionado del modelo. Windows no devuelve embeddings desde el worker ni usa referencias conocidas.
- Seleccionar profesor y reasignar un item de revisión existen; rename, merge y reassign/split general no.
- El transcript completo suele persistirse antes de diarizar, pero no hay un modelo explícito “ASR original inmutable + anotaciones humanas”.

Conclusión: `Persona 0` tiene al menos una causa determinista que debe corregirse antes de experimentar con ML. Un fallo no puede sintetizar un speaker. Un único cluster no se declarará fallo sólo por cardinalidad; será posible colapso únicamente con evidencia contradictoria.

## 4. Invariants de release de v0.8.0

1. Cada intento tiene owner, `SessionAttemptID`, generaciones y un resultado terminal observable.
2. Cancelar startup, rebind o stop invalida callbacks tardíos, libera recursos y no deja que una operación nativa no cooperativa bloquee la UI ni reactive otra sesión.
3. Transporte y contenido se distinguen: sin callbacks, callbacks silenciosos y audio audible no son el mismo estado ni activan fallback implícito; la aceptación VAD/ASR de voz queda diferida.
4. La fuente online se elige explícitamente entre aplicación y system output/global; las APIs de macOS y Windows permanecen nativas a cada plataforma.
5. System output/global requiere una acción afirmativa y consentimiento nuevo para cada intento; no existe hot-switch ni activación automática.
6. El master durable conserva el formato fuente acordado (sample rate, canales y precisión); 16 kHz mono es sólo el derivado ASR.
7. `master.raw` + manifest son la fuente de verdad de una sesión nueva; `source.wav` es un derivado separado y válido para el pipeline ASR.
8. El frame clock y los gaps son monotónicos durante rebinds; el lookahead del converter no crea silencio sintético y el tail no se suma dos veces.
9. La escritura/finalización durable es authoritative: un fallo de storage/master nunca se transforma en éxito porque exista un derivado parcial.
10. Sólo un fallo de fuente de una aplicación puede ofrecer la sugerencia explícita de system output; un fallo durable/storage nunca la ofrece.
11. Stop es single-flight y la finalización no permite iniciar otra grabación hasta que el intento anterior haya terminado de forma observable.
12. No se trunca audio silenciosamente; toda limitación de formato queda registrada y visible como pendiente o fallo.
13. Se conservan master/audio original, transcript ASR original, metadata y correcciones humanas; recovery y reproceso no los destruyen.
14. Sesiones históricas de v0.7 siguen siendo legibles por el camino legacy y se migran sólo de forma aditiva y atómica.

## 5. UX y modelo de estado

Captura y ASR avanzan en paralelo; no se modelarán en un enum monolítico.

Los ejes y tokens de estado, su ownership y su persistencia estable forman
parte de v0.8.0. La implementación nueva de VAD/aceptación ASR, circuit
breaker y prewarm queda en el roadmap posterior; estos nombres de estado no
convierten ese trabajo diferido en un gate de esta release.

`CapturePhase`: `idle`, `validatingSource`, `connecting`, `waitingForFrames`, `framesSilent`, `audioAudible`, `recording`, `stopping`, `failedRecoverable`, `failedTerminal`.

`AsrPhase`: `idle`, `preparingDownload`, `preparingLoad`, `waitingForSpeech`, `transcribing`, `retryScheduled`, `unavailableForSession`, `failedRecoverable`.

`SessionPhase` cubre el lifecycle durable: `draft`, `starting`, `recording`, `stopping`, `processing`, `complete`, `cancelled`, `recoverable`, `failed`. Ninguno se persiste como texto localizado.

La UI deriva mensajes de la combinación y muestra como mínimo: validando fuente, conectando captura, esperando audio, audio recibido, preparando modelo, transcribiendo, grabando sin ASR y error recuperable.

### Progreso

- Captura: fuente/scope, callbacks, RMS/peak y presencia de voz.
- Descarga/carga/prewarm ASR: diseño diferido de Fase 3; si se implementa,
  conserva progreso real, cancelación y ownership separados.

### Acciones recuperables

- Sin callbacks: revisar/actualizar/reintentar/otra app y `Capturar audio del equipo`.
- Callbacks silenciosos: explicar conexión sin señal; esperar, reproducir audio, reintentar o global.
- Audio audible sin voz: grabar y mostrar “audio recibido, esperando voz”; no es error automático.
- ASR no disponible: mantener stop/export/audio, permitir retry y reproceso posterior.
- Global siempre abre confirmación de alcance antes de empezar/reiniciar captura.

## 6. Arquitectura de startup, captura y recuperación

### Ownership y cancelación

Cada intento obtiene `SessionAttemptID`, token raíz y componentes hijos. Toda transición/callback incluye ese ID; resultados viejos se descartan. Cancelar invalida la generación, cancela waits/descarga/backoff, detiene captura y escritura, termina el worker ASR si era propiedad de la clase, persiste estado coherente y devuelve UI sin esperar una llamada nativa no cooperativa.

No cuenta como cancelación real envolver una llamada síncrona en `Task` y dejarla en una cola compartida.

### Boundary supervisado para ASR

La frontera de supervisor/protocolo forma parte de la arquitectura de Fase 1;
la entrega completa del pipeline ASR queda diferida a Fase 3. Cuando se ejecute,
carga e inferencia nativas usarán un worker supervisado y reiniciable:

- macOS: helper firmado con protocolo versionado por pipes/XPC; aloja FluidAudio/Core ML.
- Windows: helper .NET/native con protocolo versionado por named pipes/stdio; aloja Whisper.net/whisper.cpp.

El supervisor termina el proceso en cancelación, deadline, crash o falta de heartbeat. Así Core ML/Whisper no bloquea stop o la clase siguiente. El worker recibe paths ya validados y audio derivado, y devuelve progreso/resultados tipados.

La separación completa de descarga/carga, la reanudación, el progreso de
modelos y los deadlines específicos de ASR quedan diferidos a Fase 3. El
supervisor/protocolo de Fase 1 conserva la frontera de cancelación y
terminalización que v0.8.0 sí exige.

### Presupuestos de lifecycle, no timeouts gigantes

Cada fase de startup, captura, rebind y stop tiene presupuesto
configurable/testeable. Al agotarlo: conexión sin callbacks → error
recuperable; silencio → advisory; una llamada nativa no cooperativa → frontera
supervisada y fallo terminal observable. Cambiar un número no puede ser la
única corrección de un componente no cancelable. El circuito de ASR y la
política de `recordingWithoutAsr` pertenecen al roadmap posterior de Fase 3.

### Precalentamiento — diferido a Fase 3

El prewarm, la descarga separada y el backlog ASR se conservan como diseño
posterior. No son requisito de estabilidad de v0.8.0 ni deben retrasar la
captura durable cuando se implementen.

### Línea de tiempo ASR — diferida a Fase 3

El master durable y su frame clock son la fuente de verdad de v0.8.0 y se
describen en §7 y la caracterización de 2D. Leer backlog ASR desde disco,
mantener cursores por timestamps y abrir un circuito vivo son requisitos
posteriores de Fase 3; nunca deben rebajar la fidelidad ni truncar el master.

## 7. Captura y fallback global

### Comportamiento común

`CaptureSource.scope`: `microphone|application|systemOutput`. Metadata: tipo, nombre, identidad estable, PID inicial sólo diagnóstico, formatos nativo/master/ASR y gaps. PIDs no son identidad durable.

La señal se clasifica en dos capas: transporte (sin callback vs frames) y
contenido (silencio/noise floor y audio audible). RMS/peak detecta
señal/clipping; la aceptación VAD/ASR de voz queda diferida a Fase 3. Silencio
legítimo genera advisory, nunca cambio automático o error terminal.

### macOS

- Aplicación: `CATapDescription` por procesos, excluyendo ClassScribe.
- Global: `CATapDescription(stereoGlobalTapButExcludeProcesses:)`, excluyendo ClassScribe/helpers.
- Reenumerar identidad bundle/ejecutable al validar, justo antes del tap, ante lifecycle y al entrar en no-callbacks/silencio inesperado. Reconciliar o reiniciar tap con generation ID y registrar gaps.
- Chrome/Teams/Zoom: validar PIDs realmente traducidos a Core Audio, no sólo POSIX.
- Setup sale de `MainActor`. Si fault injection prueba que ignora cancelación, captura online pasa a helper supervisado antes de release; no se aceptan threads huérfanos por intento.

### Windows

- Aplicación: WASAPI Application Loopback con `IncludeTargetProcessTree`; revalidar identidad de ejecutable/package y reconstruir ante root reemplazado.
- Global: WASAPI loopback del render endpoint seleccionado/default. Registrar cambios; no saltar silenciosamente de dispositivo.
- No depender sólo de ventana visible para una identidad elegida; refrescar al fallar/no recibir audio.
- Cancelar activación, primer paquete, escritura y teardown. Si una llamada nativa no coopera, aplica el mismo gate de aislamiento.

### Fidelidad

- El master no será 16 kHz mono por conveniencia.
- Para app/global, conservar sample rate/canales del mix hasta estéreo y precisión PCM razonable; registrar conversión.
- Derivar 16 kHz mono sólo para VAD/ASR, sin necesidad de duplicar el master.
- `source.wav` legacy 16 kHz mono sigue válido.
- `master.raw` no está limitado por RIFF; `source.wav` es WAV dentro del
  contrato actual. RF64, W64 o segmentación requieren fixture y evidencia de
  Fase 2E; nunca se trunca silenciosamente.

### Consentimiento/privacidad

La confirmación global enumera notificaciones, otras apps, navegador, reproductores y sistema; muestra dispositivo y exclusiones. El usuario confirma inequívocamente. Se registra localmente versión de copy/timestamp como evidencia UX, no como permiso para futuros cambios automáticos. Cancelar mantiene la fuente anterior.

## 8. Voz, idioma y aceptación — roadmap posterior a v0.8.0

El siguiente pipeline se conserva como diseño de Fase 3. No es criterio de
aceptación de la frontera estable actual; la existencia del derivado
`source.wav` y su preservación sí pertenece a Fase 2D.

Pipeline común:

1. Capturar master.
2. Derivar 16 kHz mono preservando timestamps.
3. Medir RMS/peak/clipping.
4. VAD con hysteresis, duración mínima y padding calibrados.
5. Enviar sólo ventanas con evidencia de voz, conservando contexto.
6. Configurar idioma antes de decoder.
7. Evaluar no-speech, logprob, entropy/compression, confidence y estabilidad disponibles.
8. Aceptar/diferir/rechazar antes de incorporar al transcript.

Energía no es VAD; VAD no certifica texto. Thresholds son por backend y fixtures. Métricas van a diagnostics, no al texto visible.

### macOS

- Usar `VadManager`/Silero de FluidAudio con estado streaming/config versionada.
- Mantener `FluidAudio.Language` en toda inferencia.
- El filtro de script no cuenta como restricción es/en/fr. Parakeet queda sólo si VAD + aceptación + decoder superan la suite.
- Si falla, usar backend local con forced-language real o mejora upstream mantenible; no lista casera de palabras.
- Vocabulario CTC sólo rescora con voz aceptada y se prueba vivo/final.

### Windows

- Mantener `WithLanguage(es|en|fr)` y transcripción, no autodetección.
- VAD local antes de Whisper; sherpa-onnx Silero es compatible con el stack.
- Exponer no-speech/logprob cuando sea posible; si Whisper.net no lo proyecta, extensión mínima o VAD previo como señal primaria.
- Prompt técnico sólo con voz; probar mejora sin falsos positivos.

### Gate de idioma

Corpus pequeño/versionado por idioma: silencio digital; room tone/ventilador/clicks/música/notificaciones; voz elegida con/sin vocabulario; voz clara en otro idioma; voz débil/pausas/fronteras. Falla si no-speech produce frase, el backend ignora sistemáticamente idioma o vocabulario aumenta falsos positivos. Code-switching real se prueba aparte.

## 9. Diarización, identidad y correcciones — roadmap posterior a v0.8.0

Este modelo describe la renovación de Fase 4 y no exige completar su overhaul
para v0.8.0. La compatibilidad de persistencia debe conservar cualquier
transcript original y corrección humana ya existentes.

### Modelo canónico

- `SpeakerID`: UUID estable de ClassScribe por sesión.
- `EngineClusterID`: label efímero diagnóstico; nunca visible ni identidad durable.
- `displayName`: editable; default localizado (`Persona 1`, `Speaker 1`, `Personne 1`) sin cambiar ID.
- `identityState`: `unknown|candidate|confirmed`; `role`: `unknown|professor|participant`.
- `DiarizationProposal`: corrida inmutable con versiones, spans, clusters, embeddings/centroides y métricas disponibles.
- `SpeakerCorrectionOverlay`: operaciones humanas versionadas sobre IDs/segmentos.
- `SegmentID`: UUID persistido, no índice. Resegmentación reconcilia por tiempo/evidencia y manda conflictos a review.

### Precedencia

1. Corrección humana.
2. Referencia conocida que supera gate completo.
3. Propuesta actual.
4. `unknown/review`.

Reprocesar crea propuesta y la compara con overlay; nunca reemplaza rename, merge, reassign o professor confirmado. Sólo una acción explícita descarta una corrección.

### Fallos/colapso

- Cero spans, crash, timeout, output inválido o cobertura insuficiente → unknown/review.
- Un cluster válido se muestra como Persona 1/equivalente, nunca Persona 0.
- Un cluster no es fallo solo. `possibleClusterCollapse` exige evidencia contradictoria (referencias distintas, embeddings separables, discontinuidades/distancias calibradas).
- Si una plataforma no expone calidad/embeddings, declara `unavailable`, no `1`.
- Separar cobertura temporal, calidad cluster y confianza de identidad; no ocultarlas en un número.

### Referencias conocidas

Registrar ID local, materia, backend/model/version, dimensión, normalización, duración, calidad y fecha. No comparar incompatibles. Exigir calidad/duración, score calibrado, margen sobre segundo candidato y no contradicción humana. Windows devuelve embeddings compatibles o declara función no disponible; no finge paridad.

### UX

- Rename cambia displayName, no ID.
- Merge reversible mapea IDs a canónico conservando origen.
- Reassign mueve segmentos a speaker/unknown.
- Split sólo en límites de segmento/VAD/timestamp; no promete separar overlap.
- Mark professor es corrección explícita de máxima precedencia.
- Review cubre baja calidad/cobertura, overlap, unknown, conflicto o posible colapso.
- El original completo y cada propuesta siguen accesibles.

## 10. Localización — roadmap posterior a v0.8.0

La separación de idioma UI/ASR y la localización nativa completa son requisitos
de Fase 5, no gates de la frontera estable de v0.8.0.

### Settings

- `transcriptionLanguage=es|en|fr`, por sesión y opcionalmente último valor de creación.
- `interfaceLocale=system|es|en|fr`, setting persistido de aplicación.
- `system` sigue el SO soportado con fallback documentado.
- Cambiar UI no cambia sesión, modelo ni idioma ASR.

### macOS

String Catalog único; `LocalizedStringResource`/`String(localized:)` también en errores/accesibilidad; locale en root environment para refresh. Reconstruir componentes AppKit que no reaccionen sin reiniciar app. Persistir fuera de metadata de clase.

`.resx` neutrales + satélites `es/en/fr`; `ResourceManager` y `CurrentUICulture`/`DefaultThreadCurrentUICulture`; bindings notificables o reconstrucción de ventana conservando ViewModel. Sin cientos de `if language`.

### Inventario y docs

Cubrir botones, estados, errores, tooltips, accesibilidad, diálogos, historial, exportación, onboarding, idiomas, captura, ASR y diarización. Tokens de dominio estables se localizan al presentar.

`README.md`, `README.en.md`, `README.fr.md` se enlazan. Sólo docs realmente de usuario (p. ej. guía Windows) se traducen. SPEC/PLAN/arquitectura/handoff quedan únicos.

## 11. Persistencia y compatibilidad

### Schema v2 aditivo

`schemaVersion: 2` y tokens no localizados. Registra session phase, idioma ASR, capture scope, formatos, versiones backend/model/config, referencia a ASR original, proposals/overlay y gaps/diagnostics sin datos sensibles innecesarios. Idioma UI queda fuera. Escritura atómica; no borrar/reemplazar antes de validar.

### Legacy

- Sin idioma → español.
- `online` → `application`; `inPerson` → `microphone`.
- Estados raw español/aliases Windows → tokens v2.
- Labels legacy generan `SpeakerID` determinista dentro de sesión; Persona 0 se importa como nombre legacy, no evidencia.
- Sin spans válidos → unknown aunque haya label viejo.
- Referencias sin model/version/dimensión se conservan, pero no se usan automáticamente.

Abrir no reescribe. Primera modificación migra atómicamente y mantiene recuperables audio/metadata/exports. ASR original es append-only/inmutable por corrida; edición/speakers son overlays/proposals. Exporters resuelven vistas sin destruir fuentes.

## 12. Privacidad y seguridad

- Local, sin nueva telemetría/servicio remoto.
- Descargas de orígenes fijados con integridad previa a carga.
- Helpers: protocolo versionado, validación de paths/longitudes, mínimo privilegio, límites de mensajes, heartbeat/lifecycle.
- Global excluye ClassScribe/helpers si la API permite y muestra scope durante grabación.
- Logs sin audio, transcript, embeddings o materia por defecto; usar IDs opacos/métricas.
- Referencias locales y eliminables.
- UI/docs recuerdan consentimiento legal; global no lo modifica.

## 13. Acceptance criteria de la frontera estable

Esta lista define la aceptación de v0.8.0 en el checkpoint actual. Los gates
de ASR/VAD, speakers y localización completa están en el roadmap posterior y
no se reinterpretan como requisitos ocultos de RC.

### Arquitectura, lifecycle y estado

- Cada intento tiene `SessionAttemptID`, generaciones, estados estructurados y
  tokens persistibles no localizados.
- Cancelar startup, rebind o stop cierra captura/escritura, invalida callbacks
  tardíos y deja un resultado terminal observable.
- Ninguna espera de callback, captura, teardown o worker no cooperativo bloquea
  la UI, el stop ni el intento siguiente.
- La clasificación distingue sin callbacks, callbacks silenciosos y audio
  audible sin activar fallback implícito; no agrega una aceptación VAD nueva.

### Identidad, captura y consentimiento

- La identidad de una aplicación no depende sólo del PID; macOS revalida la
  identidad Core Audio y Windows detecta root/helper reemplazado.
- La captura de aplicación y system output/global usa el backend nativo de cada
  plataforma y conserva scope, endpoint, generaciones y gaps observables.
- El CTA de system output sólo aparece para el fallo de fuente de una
  aplicación; no aparece por fallo durable, storage, ASR, diarización,
  exportación o historial.
- System output/global nunca se activa sin consentimiento afirmativo nuevo por
  intento; cancelar el modal conserva la fuente anterior y no crea artefactos.
- La exclusión de ClassScribe/helpers y el cambio de output device no producen
  captura propia ni un cambio silencioso de fuente.

### Master, derivado y recovery

- `master.raw` y `audio-manifest.json` son la fuente durable de una sesión
  nueva; el master conserva sample rate, canales y precisión acordados.
- `source.wav` es un WAV 16 kHz mono separado, válido para el pipeline ASR y
  regenerable desde el master sin sustituirlo.
- El `MasterFrameClock` conserva el presupuesto entre generations/formats;
  gaps, lookahead y tail no alteran ni duplican la duración.
- Stop es single-flight; una grabación nueva se rechaza mientras la
  finalización anterior aún es authoritative.
- Un fallo tipado de master/storage domina el resultado de stop aunque exista
  un derivado parcial; deja la sesión recoverable y no ejecuta procesamiento
  final como si fuera success.
- Sólo un fallo `source` de aplicación puede recomendar system output. Un
  fallo `durableMaster`, storage o finalización nunca lo recomienda.
- No hay truncación silenciosa. La recuperación conserva master, manifest,
  audio original, transcript ASR original y correcciones humanas.

### Compatibilidad

- Las golden sessions v0.7 de macOS y Windows abren, exportan y reprocesan sin
  borrado; la migración es aditiva y atómica.
- Un nuevo intento no hereda fallo durable, consentimiento, capability ni
  estado de una generación anterior.

## 14. Tests mínimos de la frontera estable

Desarrollo `focused → subsystem`; sólo duplicar niveles si protegen fallos
distintos. Los tests de requisitos diferidos se ejecutan con su roadmap, no
son gates de esta release.

| Failure mode | Nivel mínimo |
|---|---|
| Estado, cancelación y callbacks tardíos | unit determinista + integración capture/worker |
| Sin callbacks/silencio/audible | unit de salud + integración adapter |
| Identidad/PID/root cambia | unit de reconciliación + integración específica por SO |
| Consentimiento y fallback | state-machine enumerando transiciones |
| Master clock/resampling/gap/tail | unit de contrato + integración de writer |
| Master/storage durable failure | unit de stop + integración de control plane |
| Stop single-flight/finalización | unit concurrente + integración de lifecycle |
| Derivado `source.wav` y recovery | round-trip de artefactos |
| Legacy | golden fixtures v0.7 de ambas plataformas |

Tests de tiempo usan reloj inyectado; no duermen minutos. Fixtures de audio
tienen procedencia/licencia.

## 15. Gates de release y gates físicos/manuales

La aprobación arquitectónica y la evidencia local de 2D no equivalen a
multiplatform release readiness. Cada gate de esta sección debe ejecutarse con
el artefacto y el entorno objetivo; un gate no ejecutado queda **PENDING** o
**SKIPPED**, nunca **PASS** por inferencia.

### macOS

- Build/tests locales del target activo: **PASS** en este baseline; volver a
  ejecutar como gate de RC.
- TCC de audio y micrófono, limpio/denegado/aceptado: **PENDING — SKIPPED —
  TCC**.
- CATap real de aplicación y global con audio audible, exclusión de
  ClassScribe/helpers y teardown: **PENDING**.
- Identidad/rebind de una aplicación real con root/helper creado, cerrado y
  reemplazado: **PENDING**.
- System output con consentimiento explícito por intento: **PENDING físico**;
  control-plane local de 2C.2 **PASS**.
- Cambio real de output device, gap y ausencia de hot-switch: **PENDING**.
- Rate, canales y duración del master; `source.wav` válido y separado:
  **PENDING físico**; contratos locales **PASS**.
- Stop, recovery y ausencia de callbacks posteriores: **PENDING físico**;
  evidencia local **PASS**.

### Windows

- `dotnet restore/build/test`: **SKIPPED — dotnet/csc unavailable**.
- Lanzamiento real de la aplicación: **PENDING**.
- Application loopback en una app real con root/helper reemplazado y rebind:
  **PENDING**.
- System output/render endpoint real, consentimiento por intento y exclusión
  de cambios silenciosos: **PENDING**.
- Cambio de endpoint: **PENDING**.
- `master.raw`, manifest y `source.wav` válidos, rate/canales/duración:
  **PENDING / SKIPPED — runtime Windows unavailable**.
- Escritura durable, recovery, Stop single-flight y rechazo de start durante
  finalización: **PENDING / SKIPPED — runtime Windows unavailable**.

### Ambas plataformas

- Abrir, exportar y reprocesar legacy sin perder audio, transcript original ni
  correcciones: **PENDING** como matriz multiplatform.
- Fallo de aplicación nunca autoswitch a system output; fallo durable/storage
  nunca ofrece esa sugerencia: **PENDING** como gate de producto.
- System output siempre exige consentimiento nuevo y explícito: **PENDING**
  como gate físico cruzado.
- Ningún camino trunca silenciosamente el master: **PENDING** con evidencia de
  fixture representativo.
- Fixture de clase larga representativa dentro del contrato WAV actual:
  **PENDING**; si bloquea una duración razonable, abre un correctivo focalizado
  de Fase 2E antes de RC.

Registrar SO, hardware, dispositivo, app fuente, backend/modelos, pasos,
resultado y artefactos no sensibles.

### Política de release

- La arquitectura puede aprobarse mientras un gate físico siga pendiente; una
  release estable no.
- El RC de v0.8.0 sólo se corta después de ejecutar los gates requeridos de
  macOS y Windows.
- Stable requiere un RC probado en ambas plataformas.
- No se publica una plataforma como stable ignorando la otra.
- Un hallazgo vuelve al correctivo focalizado correspondiente; no reabre por sí
  solo el roadmap diferido.

## 16. Estrategia multiplataforma de la frontera estable

| Requisito | Común | macOS | Windows | Diferencia justificada |
|---|---|---|---|---|
| Lifecycle/cancelación | attempt, generation, terminalización | CATap/AudioTapLib | WASAPI/worker | APIs y teardown nativos distintos |
| Salud de señal | transporte + contenido | callbacks CATap | paquetes WASAPI | formatos y callbacks distintos |
| Captura app/identidad | scope + identidad durable | CATap + reenumeración | Application Loopback + árbol SO | lifecycle PID/API distintos |
| System output | consentimiento + endpoint/master | stereo global CATap | render endpoint WASAPI | mix por procesos vs endpoint |
| Master/ASR | master fiel + `source.wav` derivado | Float32/source-rate | formato efectivo/WASAPI | formatos nativos distintos |
| Stop/recovery | single-flight + failure dominance | executor/tap | `StopAsync`/storage | owners de finalización distintos |
| Persistencia | manifest/schema aditivo + legacy | carpeta de sesión macOS | LocalApplicationData/ACL | almacenamiento nativo distinto |

Las decisiones de VAD/ASR, speakers y localización mantienen sus diferencias
en las secciones diferidas y no bloquean esta frontera.

## 17. Riesgos y decisiones de release

### Riesgos

1. Los gates físicos de TCC, CATap global, device-change, Windows y audio real
   no están ejecutados en este host.
2. El runtime/compile Windows no está disponible (`dotnet`/`csc`), por lo que
   la evidencia Windows local no se presenta como PASS.
3. El master fiel aumenta almacenamiento y exige evidencia de duración antes
   de adoptar un contenedor alternativo.
4. Browsers/meeting apps pueden cambiar topología; rebind y gaps deben quedar
   visibles en el gate real.

### Decisión provisional de Fase 2E

- `master.raw` no está limitado por RIFF.
- `source.wav` sigue siendo WAV y se materializa dentro del contrato actual.
- No se elige RF64, W64 ni segmentación sin fixture y evidencia reproducible.
- La truncación silenciosa está prohibida.
- Fase 2E queda **DIFERIDA / NOT STARTED** y sólo se adelanta si el fixture de
  clase larga demuestra que el contrato WAV actual bloquea una duración
  razonable; el hallazgo vuelve a un correctivo focalizado.

### Decisiones posteriores

Backend macOS forced-language, VAD/no-speech, circuit breaker/backlog,
embeddings/speakers, locale y transporte exacto de helpers se decidirán con
fixtures y gates posteriores. No se asignan números de versión futuros en esta
SPEC.
